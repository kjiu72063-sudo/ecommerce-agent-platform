### 状态机 JSON 格式

```json
{
  "name": "task",
  "description": "Task 状态机",
  "transitions": {
    "created": ["validated", "cancelled", "expired"],
    "validated": ["queued", "failed", "cancelled", "expired"],
    ...
  },
  "terminal_states": ["succeeded", "failed", "cancelled", "expired"],
  "initial_state": "created"
}
```

### 状态机设计原则

1. **明确迁移**：每个状态都有允许的目标状态列表
2. **终态不可逆**：终态没有出边
3. **初始状态**：每个状态机有且只有一个初始状态
4. **事件驱动**：每次迁移必须产生 Event

## 关键设计决策

### 1. 无效示例的作用

- **测试 Schema 验证**：确保 JSON Schema 正确拒绝错误数据
- **测试 Pydantic 验证**：确保 Python 模型正确拒绝错误数据
- **文档化常见错误**：帮助开发者避免常见错误

### 2. 状态机的作用

- **状态管理**：定义合法的状态迁移
- **防止非法迁移**：拒绝不合法的状态变更
- **事件驱动**：每次迁移产生不可变 Event
- **可恢复性**：从 Event 重建状态

### 3. 终态设计

```
终态没有出边，表示：
- 状态不可再变更
- 资源已到达最终状态
- 后续操作应创建新资源
```
