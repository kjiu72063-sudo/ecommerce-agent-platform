# 错误码词汇表详解

> 文件位置：`vocabularies/error-codes.json`
> 作用：定义所有平台标准错误码及其分类

---

## 文件结构

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "api_version": "agent-platform/v1alpha1",
  "codes": [
    {
      "code": "EXTRA_FIELD_FORBIDDEN",
      "category": "validation",
      "http_status": 422,
      "description": "包含未声明的额外字段"
    },
    ...
  ]
}
```

---

## 错误码分类

### 1. validation（验证错误）- HTTP 422

| 错误码 | 说明 |
|---|---|
| EXTRA_FIELD_FORBIDDEN | 包含未声明的额外字段 |
| HERMES_PROPOSAL_NOT_ACTIVATABLE | Hermes 提案不能直接激活 |
| IDEMPOTENCY_REQUIRED | 有副作用操作必须支持幂等 |
| PROMPT_ORDER_DUPLICATE | Prompt 片段顺序重复 |
| LOOP_HARD_LIMIT_REQUIRED | Loop 必须有硬停止条件 |
| TASK_IDEMPOTENCY_REQUIRED | Task 必须有幂等键 |
| EXACT_VERSION_REQUIRED | 必须使用精确版本 |
| MODEL_FALLBACK_TRIGGER_REQUIRED | 模型回退必须有触发错误码 |
| TOOL_CALL_IDEMPOTENCY_REQUIRED | 有副作用 ToolCall 必须有幂等键 |
| ARTIFACT_LOCATOR_SECRET | Artifact 位置包含凭证 |

### 2. authorization（授权错误）- HTTP 403

| 错误码 | 说明 |
|---|---|
| MODEL_PROVIDER_NOT_ALLOWED | 模型供应商不在白名单 |
| DEFAULT_DENY_REQUIRED | 默认决策必须是 deny |
| PERMISSION_DENIED | 权限拒绝 |

### 3. budget（预算错误）- HTTP 422

| 错误码 | 说明 |
|---|---|
| CONTEXT_BUDGET_EXCEEDED | Context Token 预算超限 |

### 4. conflict（冲突错误）- HTTP 409

| 错误码 | 说明 |
|---|---|
| DYNAMIC_ACTIVATION_SEQUENCE_INVALID | 动态激活序号不连续 |
| DYNAMIC_DEPENDENCY_DUPLICATE | 动态依赖重复激活 |
| MODEL_SELECTION_CURRENT_MISMATCH | 当前模型选择与历史不匹配 |
| CHECKPOINT_SEQUENCE_INVALID | Checkpoint 序号无效 |
| EVENT_SEQUENCE_INVALID | Event 序号无效 |
| STATE_TRANSITION_NOT_ALLOWED | 状态迁移不允许 |
| LEASE_EXPIRED | Worker 租约已过期 |
| FENCING_TOKEN_STALE | Fencing Token 已过期 |

### 5. approval（审批错误）- HTTP 409

| 错误码 | 说明 |
|---|---|
| APPROVAL_ALREADY_CONSUMED | 一次性审批已被消费 |
| APPROVAL_REQUIRED | 需要审批 |

## 使用场景

### 1. Pydantic 验证

```python
from pydantic import ValidationError

try:
    model.model_validate(data)
except ValidationError as e:
    # 返回对应错误码
    return {"error_code": "EXTRA_FIELD_FORBIDDEN", "message": str(e)}
```

### 2. API 响应

```json
{
  "error": {
    "code": "PERMISSION_DENIED",
    "category": "authorization",
    "message": "User does not have permission to access this resource",
    "http_status": 403
  }
}
```

### 3. 一致性测试

```python
def test_error_codes_unique():
    vocabulary = json.loads(Path("vocabularies/error-codes.json").read_text())
    codes = [item["code"] for item in vocabulary["codes"]]
    assert len(codes) == len(set(codes))  # 错误码必须唯一
```

## 关键设计决策

### 1. 错误码格式

```
^[A-Z][A-Z0-9_]{2,127}$
```

- 全大写
- 下划线分隔
- 3-128 字符

### 2. HTTP 状态码映射

| 类别 | HTTP 状态码 | 说明 |
|---|---|---|
| validation | 422 | 请求格式错误 |
| authorization | 403 | 权限不足 |
| budget | 422 | 资源超限 |
| conflict | 409 | 状态冲突 |
| approval | 409 | 需要审批 |

### 3. 错误码唯一性

所有错误码必须全局唯一，不能重复。

## 总结

`vocabularies/error-codes.json` 定义了 24 个标准错误码，覆盖了验证、授权、预算、冲突和审批 5 大类错误。
