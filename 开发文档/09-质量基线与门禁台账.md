## 3. 后台维护 / 调度缝

30 天保留归档 `RetentionService.archive_expired` 提供**真实可调度**的两个入口，复用
`src/presale/maintenance.py`（CLI 走 async facade `archive_expired_sqlite`，HTTP 端点直接调用同步
`archive_expired_sqlite_blocking`，行为一致）：

**HTTP 端点**（供外部调度器触发，`database` 必须位于 `PRESALE_DB_DIR` 白名单根目录下）：

```http
POST /api/v1/presale/maintenance/retention/archive?tenant_id=<租户>&database=<sqlite路径>
POST /api/v1/presale/maintenance/health                      # 存活探针
```

`database` 查询参数默认 `presale.sqlite3`，且会被限制在环境变量 `PRESALE_DB_DIR`（默认当前工作目录）
解析后的根目录之内；越界返回 400。启动/调度前先设置它：

```bash
export PRESALE_DB_DIR=/var/lib/presale
```

Cron 约定示例（每日一次）：

```bash
# 每天 02:00 对 tenant-demo 执行保留归档（database 在 PRESALE_DB_DIR 根目录下）
PRESALE_DB_DIR=/var/lib/presale
0 2 * * * curl -sS -X POST \
  "http://localhost:8000/api/v1/presale/maintenance/retention/archive?tenant_id=tenant-demo&database=/var/lib/presale/presale.sqlite3"
```

**CLI**（适合脚本/手动）：

```bash
uv run python -m presale.cli --archive-expired --db <sqlite路径> --tenant <租户>
```

保留语义：仅归档 `COMPLETE` 且超过 30 天、未归档的 trace；历史 stages 保留，不物理删除；跨租户由 `tenant_id` 隔离。

## 4. 已知限制与待办

- **main 分支保护**：当前 GitHub 免费私有仓返回 403，无法启用 branch protection。升级 Pro 或转公开后应开启：要求 PR、CI 通过后再合并。
- **B4–B6**：Harness、Loop、业务 Agent 尚未实现（见 README 阶段表）。
- **SQLite 幂等 claim 的 `IntegrityError` 真并发救回**：SELECT 与 INSERT 之间的 Unique 冲突救回（含 failed 递归重claim）已通过 `SQLiteIdempotencyRepository` 的 `claim_barrier` 测试钩子**确定性覆盖**（见 `test_idempotency_repository.py` 三个用例：同 digest 恢复 / 异 digest 冲突 / failed 递归替换）。该钩子仅测试用、默认 no-op。
- **固定 `agent_run_id` + in_progress claim 会重生成**：因 `run_ref == run_id`，in_progress 的 claim 与 fresh 无法区分，重试会走 fresh 路径重新生成而非重放（幂等风险）。建议幂等用**唯一 run_id**（默认）或保证重试前完成；行为已被测试锁定（`test_fixed_agent_run_id_with_in_progress_claim_regenerates`）。
- chain 任务：新增后台周期任务时应复用 `maintenance.py`，不要在业务路径内联。
