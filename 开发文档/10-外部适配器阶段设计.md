# 10 - 外部适配器阶段设计（Purpose-first）

> 对应 V1 售前 QA 切片（`src/presale`）的下一阶段：让它可以接入真实外部依赖。
> 基线：`v1.0-presale-converged`（2026-09-15，202 passed，分支保护已启用）。

## 设计结论
- 可进入实现：**有条件**（目的、时序、LLM 提供方已定；外部向量库提供方留待 domain-modeling）。
- 当前最大风险：同时动「生成环(LLM)」与「检索环(外部向量库)」两条外部边界——需**逐环替换**，每次只替换一个环。
- 需要先解决的一问：先接哪一环？——**先 LLM 生成环**（不改变证据形状），再接外部检索。

## 目的与边界
- **目的**：让 V1 售前 QA 切片接入真实外部依赖——OpenAI 兼容 LLM 生成答案 + 外部检索/向量库取证据；同时保持租户隔离、幂等、保留、生产装配契约不变。
- **目标用户**：内部电商客服运营（同 V1）；接入真实服务时的运维/审核方。
- **成功判据**：同一委托问答接入外部实现后仍满足「同 key 同结果(幂等)、租户隔离、失败可观测、契约不满足即失败」；单环替换后系统始终可运行。
- **时序**：**同步、请求内直连**（LLM/检索调用在 `ask()` 内等待返回）。
- **做什么**：
  - 新增 `GeneratorPort`(LLM)) 与 `RetrievalPort`(外部检索) 两个可替换端口；
  - 保留 `DeterministicKnowledgeRetriever` / `PresaleAnswerGenerator` 作为端口的「开发/最小闭环实现」；
  - 新增 OpenAI 兼容 LLM 适配器 + 外部检索适配器（后续切片）；
  - 两者在装配层注入。
- **不做什么**：不改幂等状态机、租户隔离、30 天保留、`runtime.create_sqlite` 装配契约；不引入异步队列；不接未经授权的副作用。
- **不承诺**：本轮不承诺某具体向量库产品；不承诺真实 LLM 的确定性（LLM 非确定性——由「重放返回已持久结果；首次生成允许非确定」与幂等调和）。

## 模糊项与有限选择
| 决策/原词 | 隐含问题 | 当前选择 | 主要风险 |
|---|---|---|---|
| 时序 | 高延迟是否阻塞请求 | 同步直连 | LLM 延迟占请求线程，需超时 |
| LLM 提供方 | 数据外发 + 合规 | OpenAI 兼容 HTTP | 用户数据发第三方；密钥/限额管理 |
| 检索来源 | 证据如何取 | 外部检索/向量库 | 提供方、索引、运维契约未定 |
| LLM 非确定性 | 幂等如何成立 | 重放固定结果；首生成允许非确定 | 同 key 重试首生成可能不同答案 |
| 向量库提供方 | 选型 | 待 domain-modeling 定 | 锁错产品 |

## 核心数据管道
```text
输入(question, key)
  → [RetrievalPort] ← 外部向量库 / 现状 KnowledgeSource
  → [上下文: 不变]
  → [GeneratorPort] ← OpenAI 兼容 LLM / 现状确定性生成器
  → 输出(AnswerDraft, run, trace)
  └─ 幂等 / 保留 / 处置 / 装配：全部沿用契约，不动
```
- 失败出口：外部超时/拒答 → 可观测错误显式失败；幂等记录保证重试要么回放已持久结果、要么重试首次生成（非确定风险已登记）。
- **逐环替换**：先接 LLM 环（证据形状不变）→ 验证最小闭环 → 再接外部检索环 → 再验证。

## 契约摘要（端口占位）
| 端口 | 输入 | 输出 | 不变量 | 失败行为 |
|---|---|---|---|---|
| `RetrievalPort.retrieve` | question + tenant | `RetrievalResult` | 租户隔离、范围校验、status 不变量 | 外部不可用→明确失败或降级现状检索（待定） |
| `GeneratorPort.generate` | context 包 + prompt 参数 | `AnswerDraft` | 租户隔离、可回放读回 | 超时/限流/4xx→`AnswerGenerationError`；幂等重试 |

> 注：V1 实际 `retrieve` 的输入是 `ProductQuestion`（内含 tenant），`generate` 输入含 `question + RetrievalResult + run_ref + configuration_refs`。契约以源码签名为准。

## 最小闭环与验收
- 替代实现：开发环境用现状确定性生成器/检索器贯通端到端即为最小闭环；任一环异常必须显式失败，不伪造成功。
- 端到端验收：提交 → 检索 → 上下文 → 生成 → 输出 + 幂等重放 + 处置，全程租户隔离。
- 可观察证据：run/trace 记录所用 Generator/Retrieval 实现与是否命中外部；失败有 reason_code。
- 验收条件：同一 key 重放返回已持久结果；外部环契约不满足时明确失败；每次单环替换后全量测试 + 端到端仍绿。

## 切片规划（domain-modeling 之后拆 ticket）
1. **端口化 + 契约测试（行为不变）**：抽象 `RetrievalPort`/`GeneratorPort`，现有确定性实现作为默认，runner 支持注入 → 本阶段已落。
2. LLM 生成环：新增 OpenAI 兼容 `GeneratorPort` 适配器（同步 HTTP、超时/重试、密钥装配、租户隔离、`AnswerGenerationError`）。
3. 外部检索环：选型向量库提供方 → 新增 `RetrievalPort` 适配器 + 索引/运维契约。
4. 降级策略、装配（`runtime`/`create_sqlite` 注入真实实现）、跨租户回归。
