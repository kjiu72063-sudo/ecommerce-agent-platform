# 产品目的：售前商品问答 Agent

> 状态：已确认第一版方向
> 确认范围：目的优先设计阶段
> 更新时间：2026-09-06

## 1. 一句话目的

为电商平台内部的商品运营和客服运营团队提供一个**只读、带商品依据、可转人工、可追溯**的售前问答 Agent，帮助他们更快生成可靠的商品咨询回复，同时避免系统执行未经授权的业务写操作。

## 2. 第一类用户

### 直接用户

- 商品运营人员；
- 客服运营人员；
- 负责维护商品知识和审核回答质量的内部人员。

### 间接受益者

- 提出商品问题的消费者；
- 负责处理复杂或不确定问题的人工客服；
- 需要了解问答质量和运行记录的业务管理人员。

第一版不把消费者直接作为系统操作用户。消费者是问答结果的最终受益者，但当前系统首先服务内部运营团队的审核、辅助和处置流程。

## 3. 第一版真实要解决的问题

当前需要解决的问题不是“构建一个通用的多 Agent 平台”，而是：

> 内部客服或运营人员面对商品售前问题时，需要从商品资料、规则和提示词中快速找到相关信息，并生成一份有依据、可解释、必要时明确转人工的回答。

第一版重点解决：

- 商品信息分散导致的查找成本；
- 回答缺少明确商品依据；
- 模型在不确定时生成看似确定的答案；
- 无法追溯一次回答使用了哪些上下文和运行配置；
- 只读咨询场景中不应发生改价、下单、库存写入等副作用。

## 4. 核心业务管道

```text
内部客服/运营人员提交商品问题
    → 选择或绑定商品与知识范围
    → 检索候选商品知识
    → 权限和租户范围过滤
    → 组装 Agent / Prompt / Knowledge Context
    → 生成结构化回答
    → 附带依据、置信度和人工转接建议
    → 记录 Task / AgentRun / Event / provenance
```

### 失败出口

- 商品或知识范围缺失：明确提示无法回答，不生成伪造依据；
- 知识检索无结果：返回“需要人工确认”；
- 知识与问题不匹配：降低置信度并建议人工处理；
- 上下文超预算：明确失败，不静默截断关键依据；
- 契约、权限或租户过滤失败：拒绝运行并记录失败事件；
- 模型或外部只读查询失败：返回可识别的失败状态，不伪造成功。

## 5. 第一版核心输出

第一版输出不是只有自然语言字符串，而是结构化结果：

```text
answer
citations / evidence_refs
confidence
need_human
reason_codes
run_ref
```

其中：

- `answer`：面向客服或运营人员的建议回复；
- `citations / evidence_refs`：回答使用的商品资料或规则依据；
- `confidence`：明确说明是系统评估值，不等同于真实准确率；
- `need_human`：是否建议转人工；
- `reason_codes`：触发人工或失败的可解释原因；
- `run_ref`：用于追溯本次运行记录。

## 6. B0–B3 的必要性判断

| 模块 | 对第一版的判断 | 作用 |
|---|---|---|
| B0 契约基础 | 必须保留 | 固定 Agent、Task、Run、Context、Event、ToolCall 等跨模块语义 |
| B1 能力注册中心 | 保留最小子集 | 注册和版本化售前 Agent、Prompt、只读知识查询能力及其依赖 |
| B2 状态与持久化 | 必须保留最小闭环 | 记录 Task、AgentRun、Event 和结果追溯 |
| B3 Context 引擎 | 必须保留并优先扩展 | 将商品知识、规则、Prompt 和用户问题组装为可审计上下文 |
| B4 Harness | 暂不完整实现 | 第一版只需要为只读查询定义最小执行边界，不先实现完整沙箱体系 |
| B5 Loop | 暂缓 | 第一版采用单次、有界、可失败的问答流程，不先做复杂迭代 |
| B6 业务 Agent | 先实现单一售前问答 Agent | 用一条业务路径验证 B0–B3 是否真正服务业务目的 |

## 7. 当前目的不包含什么

- 不构建通用的所有行业 Agent 平台；
- 不同时实现售前咨询、直播切片和自媒体运营；
- 不把“支持多 Agent”作为第一版成功标准；
- 不把复杂 Loop、自动规划或自主协作作为第一版目标；
- 不把自然语言回答数量作为唯一质量指标；
- 不允许没有依据的回答被视为成功；
- 不把平台基础设施数量或抽象层数量作为业务进展。

## 8. 设计门禁结论

当前可以进入下一步的规格和领域建模阶段，但**暂不进入完整 B4/B5 实现**。

下一条 tracer bullet 应验证：

```text
一个内部客服/运营人员的问题
→ 一组受限商品知识
→ 一个可追溯的只读售前回答
```

只有这条路径能够稳定运行并通过验收，才决定哪些 Harness、权限、Loop 和生产持久化能力需要继续实现。
