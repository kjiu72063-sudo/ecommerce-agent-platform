# V1 版本边界：只读售前商品问答

> 状态：已确认第一版边界
> 更新时间：2026-09-06

## 1. 版本定位

V1 是一个面向电商内部商品运营/客服运营团队的售前问答辅助闭环。它验证的是：

```text
受限商品知识
→ 可控 Context
→ 有依据的回答
→ 人工转接判断
→ 可追溯运行记录
```

V1 不是完整的电商客服系统，也不是可直接面向消费者开放的自主 Agent 平台。

## 2. V1 必须包含

### 用户与输入

- 内部客服或商品运营人员提交一个商品售前问题；
- 请求必须绑定一个明确商品；V1 不支持多商品比较或商品集合；
- 请求包含租户/业务范围和调用者身份；
- 输入可以被验证、记录并关联到一次 Task。

### 知识与上下文

- 使用商品运营团队维护和审核的已发布商品知识；原型阶段使用项目内版本化 JSON 资料集；
- 对知识来源执行租户和权限范围过滤，跨租户默认拒绝；
- 记录字段/片段级知识证据：来源、版本、定位和内容摘要；
- 将问题、Agent 配置、Prompt、知识证据和规则组装为 ContextPackage；
- 上下文超预算时明确失败或转人工，不静默丢弃关键证据。

### 回答与处置

- 生成结构化回答；
- 返回回答依据；
- 返回置信度或不确定性标记；
- 返回是否建议人工处理；
- 对没有可靠依据的问题拒绝猜测；
- 无证据、证据冲突、超商品范围、涉及实时价格/库存、权限失败或系统失败时必须转人工；
- 内部用户可接受、编辑、转人工或丢弃草稿；编辑必须保留原始与编辑后版本；`accepted` 和 `edited` 都不代表已向消费者发送消息；
- V1 原型运行记录固定保留 30 天；

### 运行记录

- 创建并关联 Task；
- 创建 AgentRun；
- 记录关键 Event；
- 保存输入、上下文来源、结果和失败原因的可追溯引用；
- 能通过 `run_ref` 查询一次运行的基本记录。

## 3. V1 可以使用替代实现

为验证业务目的，V1 原型阶段允许使用：

- 内存商品知识仓储；
- 固定 JSON 商品资料；
- 确定性关键词检索；
- 模拟模型响应；
- 模拟人工转接；
- 本地 SQLite 运行记录。

替代实现必须显式标记为 prototype，不得伪装成生产能力。

## 4. V1 明确不包含

### 业务范围

- 售后、退款、投诉处理；
- 自动下单；
- 自动改价或发放优惠；
- 库存写入；
- 订单、支付和物流操作；
- 直播切片 Agent；
- 自媒体内容生产 Agent；
- 多 Agent 协作编排；
- 面向消费者的独立生产入口。

### 平台范围

- 完整 B4 Harness；
- 通用 MCP、HTTP、gRPC、Local Tool 全协议执行器；
- 容器级沙箱和资源隔离；
- 复杂 RBAC + ABAC 统一权限平台；
- 完整审批中心；
- B5 多策略 Loop；
- 自动规划、自主反思和无限重试；
- 跨租户知识访问；
- 多模态素材注入；
- 生产级 RAG 编排平台。

## 5. V1 不承诺

V1 不承诺以下生产属性：

- 消费者可直接使用；
- 自动回答准确率达到某个未经测量的百分比；
- 模型不会产生幻觉；
- 知识内容天然完整、实时或无冲突；
- 多进程或分布式一致性；
- PostgreSQL、消息队列、对象存储生产部署；
- 高可用、灾备和跨区域恢复；
- 真实业务写操作安全；
- 自动决策替代人工客服；
- 完整合规认证。

## 6. V1 最小成功判据

在固定的商品资料集和测试问题集上，至少满足：

1. 能创建一条合法的售前问答 Task；
2. 能生成一条 AgentRun 并记录生命周期事件；
3. 回答中的每个事实性结论都能关联到已检索证据，或被标记为需要人工确认；
4. 无知识证据、权限拒绝、上下文超预算和模型失败都能显式失败；
5. 系统不会执行改价、下单、库存写入或其他业务写操作；
6. 能通过 `run_ref` 追溯输入、上下文来源、回答和失败原因；
7. 内部客服/运营人员能够判断回答是否可直接使用，或应转人工。

## 7. 进入下一阶段的门槛

只有以下内容完成后，才进入 B4 或生产化基础设施扩展：

- V1 tracer bullet 端到端运行；
- 商品知识来源和证据引用契约已冻结；
- 回答质量和人工转接规则已定义；
- 运行记录能够追溯；
- 只读权限边界通过测试；
- 失败出口有明确验收；
- 已识别哪些 B0–B3 抽象真正被业务路径使用。
