# 05: AnswerDraft 处置与留痕

**What to build:** 支持内部用户对 `AnswerDraft` 执行 `accepted`、`edited`、`escalated`、`discarded` 处置，并保存完整审计留痕。编辑保留原始草稿和编辑后版本；`accepted`/`edited` 不代表已发送给消费者。

**Blocked by:** 04

**Status:** completed

## 目标

- 四种业务处置动作可执行、可记录、可追溯；
- 编辑不覆盖原始草稿，保存编辑后版本、编辑人、时间和原因；
- `escalated` 保存转人工原因；
- `discarded` 明确记录未被采用；
- 不触发消费者消息发送或其他外部副作用。

## 输入 / 输出

- 输入：`AnswerDraft`、内部操作者、处置动作、编辑内容（可选）、转人工原因（可选）
- 输出：处置结果对象（处置类型、时间、操作者、编辑后版本或转人工记录）

## 涉及的契约

- `HumanDisposition`：`accepted` / `edited` / `escalated` / `discarded`；
- 编辑版本留痕：原始草稿不可变；
- 审计记录：操作者、时间、动作、原因。

## 验收标准

- [ ] `accepted` 只标记内部采用，不触发消费者消息发送；
- [ ] `edited` 保存编辑后版本，并保留原始草稿；
- [ ] `edited` 记录编辑人、时间和处置原因；
- [ ] `escalated` 保存转人工原因和运行引用；
- [ ] `discarded` 明确记录草稿未被采用，不篡改原始运行事实；
- [ ] 每种处置都产生可追溯的审计记录；
- [ ] 处置动作不影响技术运行状态（不错误地把 Task 标为成功或失败）。

## 拒绝 / 失败验收

- [ ] 对不存在或已处置的草稿执行处置时返回明确错误；
- [ ] 编辑内容为空或无效时不会生成错误版本；
- [ ] 处置失败不会产生无记录的动作。

## 明确不包含

- 消费者消息发送；
- 改价、下单、库存写入和支付；
- 跨租户处置；
- 完整审批流和 RBAC/ABAC 权限平台。
