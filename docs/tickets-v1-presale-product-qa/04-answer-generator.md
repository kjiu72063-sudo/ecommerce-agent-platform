# 04: ContextPackage → AnswerDraft

**What to build:** 基于 `ContextPackage` 生成结构化 `AnswerDraft`，附带依据、置信度信号、`need_human` 和原因码。V1 使用模拟生成器或模板，不接入真实模型。

**Blocked by:** 02、03

**Status:** ready-for-agent

## 目标

- 生成供内部用户审核的回答草稿；
- 输出证据引用、置信度信号、人工建议和原因码；
- 无证据、证据冲突、超范围、实时信息、权限失败或系统失败时转人工；
- 不把置信度信号伪装成准确率。

## 输入 / 输出

- 输入：`ContextPackage`、已选用 `EvidenceItem`
- 输出：`AnswerDraft`（回答文本、证据引用、置信度信号、`need_human`、原因码、配置版本引用）

## 涉及的契约

- `AnswerDraft` 通过 01 契约校验；
- `ContextPackage` 来源和 provenance；
- 模拟生成器 / 模板的确定性输出；
- 转人工原因码与规格一致。

## 验收标准

- [ ] 有字段/片段级证据时生成带引用的 `AnswerDraft`；
- [ ] 无证据时输出 `need_human=true`，不生成无依据事实；
- [ ] 证据冲突时输出转人工和冲突原因；
- [ ] 问题超商品范围或涉及实时价格/库存时转人工；
- [ ] 生成器失败时返回显式失败状态和原因码；
- [ ] 置信度信号与"准确率"含义明确区分；
- [ ] 配置和知识版本被记录在草稿关联中。

## 拒绝 / 失败验收

- [ ] 无证据时不会生成看似确定的答案；
- [ ] 失败不会被转换为空回答或伪造成功；
- [ ] 不会触发改价、下单、库存写入或外部发送。

## 明确不包含

- 处置和版本留痕（属于 05）；
- 运行追溯（属于 06）；
- 真实模型接入；
- 消费者消息发送；
- 任何业务写操作。
