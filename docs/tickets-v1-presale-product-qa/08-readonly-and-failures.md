# 08: 只读负向测试与失败出口覆盖

**What to build:** 覆盖检索、上下文和生成阶段的拒绝/失败行为，并证明完整问答流程不会触发任何业务写操作或消费者发送。

**Blocked by:** 02、03、04

**Status:** ready-for-agent

## 目标

- 验证无证据、证据冲突、跨商品、跨租户、超预算、权限失败和生成失败的行为；
- 验证只读边界；
- 防止错误被吞掉或伪装成成功。

## 输入 / 输出

- 输入：构造的无效问题、冲突资料、跨租户资料、超预算证据、失败替代服务和写操作探针
- 输出：明确的转人工/拒绝/失败结果及关键事件

## 涉及的契约

- EvidenceItem、ContextPackage、AnswerDraft；
- PermissionDecision、ToolCall；
- Task、AgentRun、Event 的失败语义。

## 验收标准

- [ ] 无证据时必须转人工或显式失败；
- [ ] 证据冲突时必须转人工，不生成确定事实；
- [ ] 跨商品和跨租户访问被拒绝；
- [ ] Context 超预算时显式失败或转人工；
- [ ] 权限失败、知识失败和生成失败均有明确原因；
- [ ] 改价、下单、库存写入、支付、订单操作和消费者发送探针均未被调用；
- [ ] 负向结果包含可追溯事件，不返回伪造成功。

## 拒绝 / 失败验收

- [ ] 任何失败不能转换成空回答；
- [ ] 任何未经授权范围的知识不能进入 ContextPackage；
- [ ] 任何业务写操作意图都被拒绝。

## 明确不包含

- 完整 B4 Harness；
- 容器沙箱和生产权限平台；
- 真实外部系统负向测试。
