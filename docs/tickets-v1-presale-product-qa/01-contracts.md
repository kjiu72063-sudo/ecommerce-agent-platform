# 01: 定义 V1 业务对象与最小输入/输出契约

**What to build:** 定义支撑 02–04 所需的最小业务对象与输入/输出契约，使 `ProductQuestion` 输入和 `AnswerDraft` 输出可以被校验和序列化。

**Blocked by:** None（可以立即开始）

**Status:** completed

## 目标

- 建立 V1 最小业务契约集，不一次定义所有对象所有字段；
- 仅覆盖主路径需要传递的输入和输出；
- 契约可被校验、序列化和重复运行。

## 输入 / 输出

- 输入：`ProductQuestion`
- 输出：`AnswerDraft`

## 涉及的契约

- `ProductQuestion`：问题文本、租户、操作者、单商品引用、幂等键、请求时间；
- `AnswerDraft`：回答文本、问题引用、运行引用、证据引用、置信度信号、`need_human`、原因码、生成时间；
- 最小平台关联引用占位（run/task/agent 配置版本引用），足以支撑追溯但不引入实现细节。

## 验收标准

- [ ] `ProductQuestion` 缺失商品引用、缺失租户、空白问题、无效幂等键时校验失败；
- [ ] `ProductQuestion` 能序列化，且保留商品、租户、操作者、幂等键字段；
- [ ] `AnswerDraft` 能在有证据或标记 `need_human=true` 时通过校验；
- [ ] `AnswerDraft` 无证据且未标记 `need_human` 时校验失败；
- [ ] 契约集仅包含支撑 02–04 所需字段，未引入未承诺的实现细节或无关对象。

## 拒绝 / 失败验收

- [ ] 无法通过的输入返回明确校验错误，不静默丢弃字段；
- [ ] 无法生成的输出返回可识别错误，而不是空回答。

## 明确不包含

- 完整 HumanDisposition 契约（属于 05）；
- 运行追溯字段（属于 06）；
- 幂等执行逻辑（属于 09）；
- 保留策略（属于 10）；
- 任何业务写操作和外部副作用。
