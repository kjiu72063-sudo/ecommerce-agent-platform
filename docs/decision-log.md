# 目的优先决策记录

> 更新时间：2026-09-06
> 阶段：接管半成品项目后的产品目的复核

## D-001：第一类用户

- **决策**：第一类用户是电商平台内部的商品运营人员和客服运营人员。
- **状态**：已确认。
- **原因**：现有 B0–B3 能力围绕 Agent、Prompt、Tool、权限、运行记录和上下文管理展开，首先服务于内部运营与审核流程，而不是直接面向消费者。
- **影响**：第一版交互、验收和权限边界以内部运营工作台/调用方为中心；消费者是间接受益者。

## D-002：第一条业务主路径

- **决策**：第一版选择只读、带依据、可转人工的售前商品问答。
- **状态**：已确认。
- **业务管道**：

  ```text
  内部客服/运营人员提交商品问题
      → 绑定商品与知识范围
      → 检索商品知识
      → 权限过滤
      → 组装 Context
      → 生成结构化回答
      → 返回依据、置信度和人工建议
      → 记录 Task / AgentRun / Event
  ```

- **原因**：现有 B6 售前咨询设计最完整，且能够直接验证 B0–B3 的实际业务价值；只读边界也能降低原型阶段的副作用风险。

## D-003：第一版不执行业务写操作

- **决策**：V1 不允许自动改价、下单、库存写入、支付、订单或站外触达。
- **状态**：已确认。
- **原因**：当前尚未完成 Harness、权限决策、审批和生产安全边界；第一条 tracer bullet 应先验证信息辅助和可追溯性。

## D-004：B4/B5 暂不作为当前主线

- **决策**：暂不直接实现完整 B4 Harness 或 B5 Loop；先用 B0–B3 验证一条业务 tracer bullet。
- **状态**：已确认为当前工作策略。
- **原因**：B4/B5 文档中包含较宽的平台范围，但现有业务路径尚未证明这些抽象都必要。提前扩展会增加返工 B0–B3 的风险。

## D-005：V1 允许替代实现

- **决策**：原型阶段允许内存知识仓储、固定 JSON、确定性检索和模拟模型，但必须显式标记为 prototype。
- **状态**：已确认。
- **原因**：先验证输入到输出的业务管道，不把真实模型、生产数据库和高风险外部副作用混入设计验证。

## D-006：当前保留的基础模块

- **决策**：保留 B0 契约、B1 最小注册能力、B2 Task/Run/Event 最小闭环和 B3 Context 组装能力。
- **状态**：已确认。
- **后续审查**：B1 完整依赖解析、B2 Checkpoint、B3 未使用的高级来源都要通过 tracer bullet 重新验证，不因已经实现就自动扩展。

## D-007：仍需在领域建模阶段确认的规则

以下事项尚未由当前目的决定，不能由实现自行猜测：

- 商品知识的权威来源和更新责任人；
- 证据引用的最小粒度；
- 置信度的计算方式和展示语义；
- 什么条件必须转人工；
- 多商品问题如何处理；
- 商品价格、库存、配送等实时信息是否进入 V1；
- 内部客服是否可以修改或纠正 Agent 草稿；
- 运行记录保存多久；
- 不同租户之间的知识隔离模型；
- 模拟模型替换为真实模型的验收标准。

这些问题应在领域建模和规格阶段解决，而不是在业务实现中隐式决定。
